# Backend defects found while rebuilding the web app

The frontend rebuild does not change `apps/api`. Each item below was found
while building against the live API. Where the web app works around it, the
workaround is named so it can be removed once the API is fixed.

| # | Area | Defect | Effect today | Web workaround |
|---|------|--------|--------------|----------------|
| 1 | Domains | Some reads resolve a domain **slug** for the domain itself but not for its child queries (senders and reports came back empty by slug, full by id). | Pages addressed by slug showed empty evidence. | Domain and setup pages look up the id from the client list and call the API with it. |
| 2 | Billing | The billing-portal session's return URL is `${BETTER_AUTH_URL}/app/billing` (`billing.controller.ts`, `billingPortalController`). The web route is `/billing`, and `BETTER_AUTH_URL` is the **API's** origin, not the app's (`APP_URL`). | A customer returning from the provider's portal lands on a 404, on the wrong host in any deployment where the two differ. | `next.config.ts` redirects `/app/billing` to `/billing` (307). That only helps where the API and app share an origin; the fix is `${env.APP_URL}/billing`. |
| 3 | Billing | `PATCH /billing/plan` with `plan: MOORING` calls `cancelSubscription` outside the `try`, so a `NO_SUBSCRIPTION` refusal is not formatted by `sendBillingError`. | A 500 instead of the 409 the screen can explain. | The billing page only offers the move to the free plan when a subscription exists. |
| 4 | Billing | `PATCH /billing/plan` always answers `{ status: "scheduled", effectiveAt: "cycle_end" }`, including on Paddle, which applies the change at once. | The response is wrong about timing on Paddle. | The screen words timing from the provider and re-reads the plan after the call. |
| 5 | Billing | The failed-payment grace length (`dunningGraceDays`) is not exposed, and `graceEndsAt` is not written by the dunning run, so `GET /billing` usually reports `graceEnds: null` during a grace that is running. | The screen cannot give the date the grace ends. | Says "a short grace period" unless the API sends `graceEnds`. |
| 6 | Billing | No endpoint returns quota usage (clients counted across the owner's workspaces, metered active domains). `buildInventory` computes `metered.activeDomains`/`countedDomains` but only export and erasure use it. | Billing shows active domains as an upper bound ("up to N"), and clients per workspace. | Usage is worded by how exact each count is. |
| 7 | Plans | `dataRetentionDays` and `auditRetentionDays` are in the plan catalog but nothing enforces them as retention. | Publishing them would be a false claim. | Never shown on pricing or billing. |
| 8 | Portal | `GET /api/portal` does not select domain `slug`, though every other domain read returns it. | Portal links built from the slug pointed at `/portal/domain/undefined`. | Portal links use the domain id, which the domain route accepts. |
| 9 | Portal | A contact invited by more than one workspace gets `400 … Pass organizationId`, with no list of which workspaces. | The contact cannot choose. | The page explains and asks them to use the provider's direct link. |
| 10 | Portal | The portal read routes have no plan check; `portal.client` is only checked when a grant is created. | A workspace that drops below Harbor keeps serving existing portal contacts. Possibly intended; needs a product decision. | None. |
| 11 | Portal | `possibleSpoofingSources[].detail` is operator prose ("Confirm with the domain owner, then enforce"). | Not suitable for the client portal. | The portal writes its own plain sentence and does not show `detail`. |
| 12 | Config | `env.ts` treats an unset `NODE_ENV` as production and refuses to start with `EMAIL_PROVIDER=console` ("Production requires EMAIL_PROVIDER=resend"). | `npm run dev` in `apps/api` fails unless `NODE_ENV=development` is set by hand. | None; start the API with `NODE_ENV=development`. |
| 13 | Plans | Every 402 `FEATURE_NOT_IN_PLAN` message opens with the raw entitlement key (`entitlement.service.ts`: "`${feature}` is not included in …"), e.g. "auth.sso is not included in Harbor". | Jargon on screen wherever the API's sentence is shown. | `planRefusalText` (lib/plan-features.ts) swaps the key for its plain label; the plan names in the sentence are kept. |
| 14 | Slack | The Slack controller answers `{ error: "message", code }` while every other route nests `{ error: { code, message } }`. | The code sat beside the message and was read as missing. | `extractErrorCode` now reads the top-level `code` when `error` is a string. |
